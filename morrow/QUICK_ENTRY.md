# Morrow 快速记账

入口：<https://enchanting-pegasus-4af56c.netlify.app/#quick-entry>。GitHub 推送后，需等待 Netlify 将对应版本发布，网址才会更新。

## 每天怎么用

首次先登录 Morrow，并在“账户与同步”中主动开启同步。以后打开快速记账，输入金额，点“保存这一笔”。分类和支付方式沿用该收支类型上次的选择；新支出默认“其他／微信”，日期默认设备上的今天，备注可不填。餐饮／微信、购物／支付宝、交通／微信可以用预设按钮选择。

手机从根网址进入时默认打开快速记账。Mac 可用上方入口或侧栏“Quick entry／快速记账”。iPhone 可在 Safari 的分享菜单选择“添加到主屏幕”；manifest 的启动地址也是快速记账。页面仍没有离线冷启动的 Service Worker，不承诺断网时能重新打开网站。

金额输入框使用小数键盘；支持 ⌘ / Ctrl + Enter 保存。视口因软键盘缩小时，保存按钮移动至可视区域底部，底部导航暂时隐藏。该逻辑通过 Chromium 视口事件测试，真实 iPhone/Safari 键盘行为仍需设备验收。

## 真实数据与原有页面

- 快速记账是真实账本：在 IndexedDB 保存，刷新后保留。登录后的空间按 Supabase 项目及用户隔离。
- 未登录空间与账户空间分开，登录不会自动上传或替换未登录记录。需要迁移时，先在原空间导出完整 JSON，登录后使用 Eras 中的恢复流程。
- 首页概览仍是演示，原页面的示例账单没有被转成真实账单。原版小满代码和 `xiaoman-v1` 不作修改。
- 手动存款余额、目标花园和日常账单独立；记账不会自动扣减或增加手动存款，不会伪造支付平台余额。
- 支持支出、收入、退款、转账，日期、备注、分类、支付方式、币种、编辑、确认删除、月份筛选、搜索和 CSV 导出。
- 退款按自身记录日期冲减支出，不计收入；转账不计入收支。记录的支付方式是标签，没有访问微信、支付宝或银行卡权限。
- 实际账单参与习惯成就、月度复盘和 Wrapped。统计按币种分开；手动记录与明确导入的历史快照合并统计，不把演示数据混入。若手动记录与历史文件包含相同交易，需要自行核对，系统不会依据相同金额猜测删除真实交易。
- 语言和外观保存在本浏览器，切换后立即生效；分类／支付方式／币种偏好跟随账本同步。

## 数据与同步实现

复用现有 `morrow_eras_read` / `morrow_eras_commit`、RLS、版本 CAS、幂等请求 ID 和本机持久化待同步快照。**无需重新运行建表脚本，也没有新建数据库表。**

顶层 `schemaVersion: 2` 保持不变，新增可选字段：

```text
ledger: {
  version: 1,
  records: [{
    id, kind, amount, currency, category, account, toAccount,
    date, note, createdAt, updatedAt, revision, deletedAt
  }],
  preferences: { currency, byKind: { expense, income, refund, transfer } }
}
```

旧快照没有 ledger 时，校验不会自动增加空字段，避免凭空制造同版本冲突。首次保存实际账单才写入扩展。金额用整数最小货币单位；求和使用 BigInt，溢出时明确报错。编辑金额和显示金额保留最小货币单位精度。业务日期用设备本地日历，不用 UTC 截取作为默认“今天”。

本机更新事务保存完整状态与同步元数据；修改使用记录 revision 检查，保存请求 ID 幂等。删除保留 deletedAt 标记，当前统计排除删除记录，历史纪念可保留。两端冲突仍采用先保存双方副本、再明确选择完整版本的流程，不做无提示的金额相加。

现有服务端验证用户身份、快照版本、基本结构和大小；详细账单金额／日期规则由客户端验证。当前仍为完整快照架构，服务端单份文档上限 8 MiB；不是服务端规范化的银行总账或可信成就认证服务。没有支付平台自动读取功能。

## 备份与恢复

快速记账的“备份与恢复”可下载完整 JSON（含账本、删除标记、Eras 和明确导入的原版备份）及实际账单 CSV。CSV 不导出已删除记录，备注中的电子表格公式前缀会转义。

JSON 格式仍为 `format: morrow-garden`，包含完整 state，可沿用 Eras 的恢复入口。恢复前必须保存当前副本并确认；确认时重新检查状态未变化。当前已有账单时，没有 ledger 的旧 Garden 备份会被拒绝，不会抹掉新账本。完整恢复仍会替换选定空间，恢复前的状态保存在 recovery 中。

## 测试结果

- 原版 4 项测试通过，Morrow/Eras/Cloud/Quick entry 共 44 项单元测试通过。
- 快速记账 Chromium：手机默认入口、只填金额、记住偏好、刷新保留、退款／转账、跨月编辑、确认删除和删除标记、未保存草稿保留、过期编辑拒绝、完整备份、旧备份保护、存储不可用时禁止保存、中英偏好保留、360/390/768/1440 布局通过。
- 两个独立 Chromium profile＋合成 Supabase API：真实账单新增／编辑／删除同步，花园余额不变，旧有幂等、响应丢失重试、离线恢复及冲突流程通过。
- 原演示首页交互、花园、Collection/Wrapped 浏览器回归通过。
- 未验证：真实用户的第二台设备、生产写入、Safari/实体 iPhone、主屏幕安装、真实软键盘。开发环境匿名访问 Netlify 站点返回 401（站点访问保护）；这与 Morrow 自己的登录不同，因此生产页面发布与实际登录结果仍需用户浏览器确认。

若 iPhone 打开时要求登录 Netlify，可使用站点访问权限进入。若以后决定公开网页界面，应在 Netlify 中明确调整站点访问设置；Morrow 用户数据仍依靠 Supabase Auth/RLS 隔离，本次没有自动改变站点访问权限。
